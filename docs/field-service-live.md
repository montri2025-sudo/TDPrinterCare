# บริการนอกสถานที่ — บันทึกงานจริง

`/field-service` เป็นคิวงานจริง อ่าน/เขียน PostgreSQL ไม่ใช้ข้อมูลตัวอย่างหรือ sessionStorage ของ Demo เดิม
เมนูใช้ชื่อ “บริการนอกสถานที่” โดยไม่มีคำว่า Demo และไม่มีข้อมูลสมมติ
URL เดิม `/field-service/demo` เปลี่ยนไปหน้าข้อมูลจริง ปุ่มแนะนำสอนแบบอ่านอย่างเดียว ไม่เติมข้อมูลตัวอย่าง

## การทำงาน

- ผู้ประสานงานสร้างใบงานจากลูกค้า/เครื่องในทะเบียน ระบุสาขา หน้างาน ที่อยู่ ผู้ติดต่อ อาการ ประเภทงาน วันเวลา ช่าง และพิกัด (ถ้ามี)
- งานเริ่มที่รับคำขอ → รอนัดหมาย → มอบหมาย → เตรียมพร้อม → เดินทาง → กำลังบริการ → รอตรวจรับ → เสร็จสิ้น
- รออะไหล่ / นำเครื่องกลับศูนย์ / ให้กลับไปแก้ไขเพิ่ม ต้องมีเหตุผล ไม่ข้ามขั้นตอน
- รายงานและ Checklist ต้องครบก่อนส่งตรวจรับ ชื่อผู้ตรวจรับต้องระบุก่อนปิดงาน (เป็นข้อความบันทึก ไม่ใช่ลายเซ็นอิเล็กทรอนิกส์)
- เปลี่ยนนัด/ช่างได้ในสถานะที่รองรับ ต้องระบุเหตุผล บันทึกนัดเดิม/ใหม่และผู้ดำเนินการในประวัติ
- ใช้ version ตรวจการบันทึกทับจากหลายหน้าจอ ข้อมูลเปลี่ยนจะตอบ 409 ต้องโหลดใหม่
- CSRF เดิมใช้กับ POST ทุกเส้นทาง แบบฟอร์มสร้างมี request key กันส่งซ้ำ

## สิทธิ์

| บทบาท | อ่าน | เขียน |
|---|---|---|
| admin | ทุกสาขา | สร้าง/นัด/รายงาน/สถานะ/แผน |
| manager, technician_lead | สาขาตนเอง | สร้าง/นัด/รายงาน/สถานะ/แผน |
| sales | สาขาตนเอง | สร้าง/นัด/มอบหมาย/แผน ไม่แก้รายงานช่างหรือขั้นตอนบริการ |
| technician | งานที่มอบหมายให้ตนเองและสาขาตรงกัน | รายงาน/ขั้นตอนช่าง/แผนตนเอง ไม่สร้างหรือมอบหมายใบงาน |
| customer / ไม่ล็อกอิน | ไม่มีสิทธิ์ | ไม่มีสิทธิ์ |

พนักงานที่ไม่มีสาขาจะถูกปฏิเสธ ต้องให้ผู้ดูแลกำหนดสาขาก่อน ข้อมูลลูกค้า/เครื่องในแบบฟอร์มสร้างใช้ทะเบียนกลางเดียวกับหน้า “ลูกค้า/เครื่อง” เดิม
การเข้าถึงใบงานและแผนตรวจที่เซิร์ฟเวอร์เสมอ ไม่พึ่งการซ่อนปุ่ม

## แผนเดินทาง

`/field-service/plans` เลือกสาขา ช่าง และวันที่ เพิ่มใบงานในวันเดียวกันเป็นจุดแวะ เรียงขึ้น/ลง นำออก และบันทึกเข้าฐานข้อมูลได้
หมุดเปิดใบงานได้ ลำดับคงอยู่หลังโหลดหน้าใหม่ รองรับ version เช่นเดียวกับใบงาน
งานที่เปลี่ยนวัน/ช่าง/ปิดแล้วจะถูกกรองออกจากแผนที่แสดง พร้อมคำเตือนให้บันทึกใหม่

งานจริงยังไม่ส่งพิกัดให้ Google: แสดงผังพิกัดและเส้นประลำดับแวะ ไม่ใช่แผนที่ถนน
ถ้ามีพิกัดสาขาและทุกจุดครบ จะแสดงค่าประมาณจากระยะเส้นตรง × 1.3 และความเร็ว 30 กม./ชม.
คำนวณเวลารอนัด เวลาบริการ ถึงช้า/นัดทับ/เกินเวลาเลิกงาน ถ้าพิกัดไม่ครบจะไม่สร้างค่าระยะทางขึ้นมา
ไม่ใช่ข้อมูลจราจรสดหรือคำแนะนำเส้นทางที่เร็วที่สุด

## ตารางและผลกระทบต่อระบบเดิม

เพิ่ม `Field_Service_Jobs`, `Field_Service_History`, `Field_Service_Plans` ด้วย CREATE TABLE/INDEX IF NOT EXISTS ใน schema.sql
ไม่มีการเพิ่มข้อมูลตัวอย่าง ไม่มี ALTER/UPDATE/DELETE ข้อมูลตารางงานซ่อม สต็อก การขาย หรือ Odoo จากโมดูลนี้
ไม่ได้เพิ่มชื่อใน db.TABLE_PK เพราะคีย์ใหม่เป็นข้อความ ไม่มี SERIAL
Dockerfile เพิ่ม COPY field_service.py ต้อง build image ใหม่

ไม่ได้เปลี่ยนการทำงานเดิมของรูปแนบ การเงิน ซิงก์ Odoo หรือไฟล์ odoo/entrypoint-wrapper.sh
ตัวเริ่มระบบ/การย้าย schema เดิมยังทำงานตามเดิม จึงต้องสำรองฐานข้อมูลก่อน deploy เช่นทุกครั้ง

## ตรวจสอบก่อน deploy

```sh
PYTHONPATH=tests/_stubs:. python3 -m unittest discover -s tests
node --test tests/*.test.cjs
```

ผลตรวจชุดถอดข้อมูลตัวอย่างและเติมเสียง: Python 111 รายการ + Node 23 รายการ ผ่านทั้งหมด
ตรวจคำบรรยายพนักงาน 70 ข้อความตรงกับ manifest และถอดรหัส MP3 ได้ครบ (รวม 441.5 วินาที)
ตรวจหน้าจอ: ทางเข้าเดโมเก่าไปหน้าจริง, คิวว่างหลังนำใบงานทดสอบออก, เล่นเสียงต่อเนื่อง พัก ปิดเสียง และหยุดได้
ทดสอบ PostgreSQL แยก: สร้างซ้ำไม่เพิ่มใบงานใหม่ ลำดับงานครบจนปิด บันทึกรายงาน/ประวัติ อ่านผ่าน connection ใหม่ และป้องกัน version เก่า
เปรียบเทียบข้อมูลทุกตารางเดิมก่อนและหลังการทดสอบโมดูล ไม่มีข้อมูลเดิมเปลี่ยน
ทดสอบหน้าจอมือถือ: สร้างใบงาน เปลี่ยนสถานะ เรียงแผน 3 จุด บันทึก และรีเฟรชแล้วลำดับยังอยู่

ชุดทดสอบในเครื่องเท่านั้น:
```sh
docker compose --env-file .env.local-test -p tdprinter-local-test -f docker-compose.local-test.json exec -T app python - < tools/seed_field_service_local_test.py
docker compose --env-file .env.local-test -p tdprinter-local-test -f docker-compose.local-test.json exec -T app python - < tools/check_field_service_local_test.py
```
ต้องมี fictional fixtures จาก tools/seed_odoo_local_test.py อยู่แล้ว เครื่องมือสองตัวนี้ปฏิเสธเมื่อไม่มี TDSP_LOCAL_TEST=1 ห้ามตั้งธงนี้บน Production

## ขึ้น Production

1. สำรองฐานข้อมูลและเก็บ image ปัจจุบันสำหรับ rollback ให้สำเร็จก่อน
2. ตรวจ git status บนเซิร์ฟเวอร์ เก็บไฟล์แก้ค้างและไฟล์สำรองเดิมไว้
3. pull สาขาที่ตรวจแล้ว จากนั้น build แอปล่วงหน้าขณะที่แอปเก่ายังทำงาน
4. เปลี่ยนเฉพาะแอปหลัก ไม่ต้องเปลี่ยน Odoo/ฐานข้อมูล:

```sh
docker compose build tdprinter-care
docker compose up -d --no-deps tdprinter-care
docker compose logs --tail=40 tdprinter-care
```

แอปอาจหยุดชั่วครู่ระหว่างเปลี่ยนคอนเทนเนอร์ ตรวจ login, งานซ่อมเดิม, คลังเดิม และหน้าบริการหลังเริ่ม
Rollback ใช้ image แอปเดิมโดยเก็บตารางบริการและข้อมูลไว้ ไม่ drop ตารางและไม่ restore ทับข้อมูลโดยไม่มีเหตุจำเป็น

## ข้อจำกัด

รุ่นนี้ไม่มีแนบภาพ/ลายเซ็นจริง ไม่มีหน้าลูกค้าเปิดเอง ไม่มีการตัดอะไหล่ การเงิน Odoo หรือจราจรสด
ปุ่มสอนใช้งานยังทำงานแบบอ่านอย่างเดียว หน้า operational มีคำบรรยายเฉพาะงานจริง
เสียงของคู่มือพนักงานและหน้าบริการนอกสถานที่ใช้ MP3 ที่สร้างออฟไลน์จากเสียงต้นแบบเดิมของเจ้าของระบบ หากปิดเสียง/เล่นไฟล์ไม่ได้จะใช้คำบรรยายตามเวลา ไม่ใช้เสียงอื่นแทน
