# บริการนอกสถานที่ (Demo รุ่นแรก)

`GET /field-service` — เมนูทดลองสำหรับส่งช่างไปติดตั้ง ตรวจเช็ก ซ่อม และบำรุงรักษาเครื่องพิมพ์ ณ โรงงานลูกค้า
**ทั้งหมดเป็นข้อมูลจำลอง** (บริษัท บุคคล เครื่อง พิกัด) แสดงป้าย “Demo / ข้อมูลจำลอง” ทุกหน้าจอและในใบงาน

## ขอบเขตและความปลอดภัยของข้อมูล
- Route ฝั่งเซิร์ฟเวอร์ (`field_service_demo` ใน `app.py` และ `field_service_google.py`) **ไม่ query ฐานข้อมูล** และไม่มี POST
- ข้อมูลอยู่ใน `static/field-service-data.js` (ซีเรียลขึ้นต้น `DEMO-`, เบอร์ `02-000-xxxx`, ผู้ติดต่อ “ตัวละครสมมติ”, ที่อยู่ “สมมติ”)
- การเปลี่ยนสถานะ Checklist บันทึกผล และแผนเดินทาง เก็บใน `sessionStorage` ของแท็บนั้นเท่านั้น ปุ่ม “ล้างข้อมูล Demo” คืนค่าเริ่มต้น
- ไม่ตัดสต็อก ไม่ออกใบเสนอราคา/ใบแจ้งหนี้ ไม่ส่งข้อความลูกค้า ไม่เรียก Odoo ไม่ขอตำแหน่งปัจจุบัน · บริการแผนที่ภายนอกใช้เฉพาะเมื่อตั้งคีย์ Google และส่งเฉพาะพิกัดจุดสมมติ
- ไม่ส่งข้อมูลจริงลงเบราว์เซอร์เพื่อ “จำลองสิทธิ์” — หน้าไม่มีข้อมูลจริงเลย

| บทบาท | มุมมอง |
|---|---|
| admin, manager, technician_lead | ห้องควบคุม, ช่าง, ลูกค้า (ตัวอย่าง), แผนการเดินทาง |
| technician | ช่าง, แผนการเดินทาง |
| sales, customer | 403 (ไม่มีเมนู) · ไม่ได้ login → ไป `/login` |

มุมมองตามบทบาทเป็นการจัดหน้าจอ เมื่อทำระบบจริงต้องจำกัดข้อมูลฝั่งเซิร์ฟเวอร์ (ช่างเห็นเฉพาะงานตนเอง ลูกค้าเห็นเฉพาะเครื่องตนเอง)

## สถานะใบงาน
ลำดับหลัก: รับคำขอ → รอนัดหมาย → มอบหมายช่าง (ต้องเลือกช่าง) → เตรียมพร้อม → เดินทาง → กำลังบริการ → รอตรวจรับ → เสร็จสิ้น
กรณีพิเศษ (ต้องระบุเหตุผล): รออะไหล่ (จากเตรียมพร้อม/กำลังบริการ → กลับไปเตรียมพร้อมเมื่ออะไหล่พร้อม),
นำเครื่องกลับศูนย์ (จากกำลังบริการ — งานจริงต้องเปิดตั๋วซ่อมแยก Demo ไม่สร้าง), ลูกค้าขอแก้ไขเพิ่ม (รอตรวจรับ → กำลังบริการ),
**นัดใหม่** (จากรอนัดหมาย/มอบหมาย/เตรียมพร้อม/เดินทาง/รออะไหล่: บันทึกเหตุผล วันเวลาเดิม → ใหม่ แล้วกลับเป็น “มอบหมายช่าง”)
ทุกการเปลี่ยนแปลงบันทึกประวัติ (เวลา สถานะเดิม/ใหม่ เหตุผล ผู้ทำ) และแสดงขั้นตอนถัดไป

การ์ดสรุป: งานวันนี้ = นัดวันนี้ · รอนัดหมาย = รับคำขอ + รอนัดหมาย · กำลังบริการ = เดินทาง + กำลังบริการ + รอตรวจรับ · รออะไหล่ · เสร็จสิ้น
(ตัวเลขคำนวณจากรายการเดียวกับตารางคิว จึงตรงกันเสมอ)

## แผนการเดินทาง
- ลูกค้าเป็นบริษัทสมมติที่ **วางบนถนนสาธารณะรอบศูนย์บริการ** (ไม่ใช่ที่ตั้งบริษัทจริง) — พิกัดชุดเดียวกันใน `field_service_google.DEMO_POINTS` และ `static/field-service-data.js` (เทสต์ตรวจว่าตรงกัน)
- จุดเริ่มต้น HQ เป็น **พิกัดโดยประมาณ** ของ 197 นวมินทร์ 86 แยก 2 — ตั้งค่าจริงด้วย `FIELD_SERVICE_HQ_LATLNG=lat,lng`
- **มีคีย์ Google (ตั้งค่าแล้ว):** ระยะทาง/เวลาจาก Google Routes API แบบ **ไม่คิดสภาพจราจร** (SKU Essentials) แสดงแผนที่ Google หมุดหมายเลข และเส้นทางขับรถจริงตามลำดับที่เลือก
- **ไม่มีคีย์ หรือ Google ล้มเหลว:** ใช้ค่าประมาณจำลอง (ระยะเส้นตรง × 1.3, 30 กม./ชม.) บนผัง SVG — ป้ายบอก “ประมาณจำลอง” และเส้นประเป็นลำดับเท่านั้น ไม่วาดเส้นตรงบนแผนที่จริง
- ถึงก่อนเวลานัดจะรอถึงเวลาเริ่มนัด · เตือน “ไปไม่ทัน” เมื่อถึงหลังช่วงนัด · เตือน “เวลานัดทับกัน” · เตือนเกินเวลาเลิกงาน
- จัดลำดับได้ทั้งลาก ปุ่มขึ้น/ลง (คีย์บอร์ด/มือถือ) ลบ เพิ่ม ล็อกลำดับ และสถานะรายจุด (ยังไม่ออกเดินทาง → เดินทาง → ถึงหน้างาน → บริการเสร็จ หรือ เลื่อนนัด)
- “แนะนำลำดับ” ใช้เวลาเดินทางชุดเดียวกับที่แสดง (Google หรือจำลอง) คงจุดที่ล็อก และ **แสดงให้ช่างตรวจ** ต้องกด “ใช้ลำดับนี้” เอง
- คลิก/Enter ที่หมุด (ทั้งแผนที่ Google และผังจำลอง) เปิดใบงาน
- ไม่มีข้อมูลจราจรสด ไม่อ้างว่าเป็นเส้นทางที่เร็วที่สุด ไม่ขอตำแหน่งปัจจุบัน

### การเชื่อม Google (ตัดสินใจแล้ว: Routes API Essentials + Maps JavaScript API)
- เบราว์เซอร์ส่งเฉพาะ **รหัสจุด** (HQ, C1…) ไปที่ ServicePro → เซิร์ฟเวอร์แปลงเป็นพิกัดแล้วเรียก Google ด้วย `GOOGLE_ROUTES_API_KEY` (คีย์อยู่เฉพาะบนเซิร์ฟเวอร์)
  ส่งให้ Google เฉพาะพิกัด ไม่มีชื่อลูกค้า เบอร์ ที่อยู่ หรือเลขเครื่อง
- `GET /field-service/google/matrix?ids=…` (Compute Route Matrix) และ `GET /field-service/google/route?seq=…` (Compute Routes, ≤10 จุดกลาง, polyline)
  ทั้งสองใช้ `TRAFFIC_UNAWARE` ไม่ใส่เวลาออกเดินทาง ไม่ใช้ waypoint optimization (คงอยู่ใน Essentials)
- เฉพาะ admin/manager/หัวหน้าช่าง/ช่างที่ login · cache ในหน่วยความจำ 24 ชม. · จำกัด 20 ครั้ง/นาที/ผู้ใช้ และ `FIELD_SERVICE_GOOGLE_DAILY_CAP` (ค่าเริ่มต้น 200 ครั้ง/วัน)
  · error ส่งกลับแบบไม่เปิดเผยรายละเอียด · ไม่มีคีย์ → 503 `not_configured` และหน้าใช้ค่าประมาณจำลอง
- แผนที่บนหน้าใช้ `GOOGLE_MAPS_BROWSER_KEY` (คีย์แยก มองเห็นได้ในเบราว์เซอร์ จึงต้องจำกัด referrer) และ Map ID (`GOOGLE_MAPS_MAP_ID`, ค่าเริ่มต้น `DEMO_MAP_ID` สำหรับทดสอบ)
- **ค่าใช้จ่ายโดยประมาณ:** เปิดแผน 1 ครั้งที่มี n จุด (รวมศูนย์) = matrix n×n element (5 จุด = 25) + 1 route ต่อหนึ่งลำดับใหม่ + 1 โหลดแผนที่;
  Essentials ฟรี 10,000/เดือนต่อ SKU แล้ว US$5/1,000 · Dynamic Maps ฟรี 10,000 โหลด แล้ว US$7/1,000 (ราคา ณ 2026-10-26)

### ขั้นตอนสำหรับเจ้าของระบบ (ทำเองใน Google Cloud Console — ผู้ช่วยไม่สร้างบัญชีหรือใส่คีย์ให้)
1. สร้าง/เลือกโปรเจกต์ ผูก Billing แล้วเปิด **Routes API** และ **Maps JavaScript API**
2. ตั้ง Budget alert (เช่น 500 บาท/เดือน) และ quota ต่อวันของ Routes API
3. สร้างคีย์ **เซิร์ฟเวอร์**: API restriction = Routes API อย่างเดียว · Application restriction = IP ของเซิร์ฟเวอร์ → ใส่ `GOOGLE_ROUTES_API_KEY` ใน `.env` บนเซิร์ฟเวอร์
4. สร้างคีย์ **เบราว์เซอร์**: API restriction = Maps JavaScript API · HTTP referrers = `https://servicepro.tdprinter.com/*` (และ `http://localhost:8000/*` ถ้าทดสอบในเครื่อง) → `GOOGLE_MAPS_BROWSER_KEY`
5. (แนะนำ) สร้าง Map ID สำหรับ JavaScript → `GOOGLE_MAPS_MAP_ID` · ตั้ง `FIELD_SERVICE_HQ_LATLNG` เป็นพิกัดจริงของศูนย์
6. รีสตาร์ต container แอป แล้วเปิด `/field-service#route` ตรวจว่าป้ายขึ้น “Google ไม่คิดจราจร”
ห้ามใส่คีย์ใน Git แชต หรือ URL · หากคีย์รั่วให้ลบ/สร้างใหม่ใน Console แล้วอัปเดต `.env`

## Demo พร้อมเสียงบรรยาย
- 17 ขั้น ครอบคลุมห้องควบคุม ใบงาน (เปิดแบบไม่บล็อกปุ่ม Demo) มุมมองช่าง ลูกค้า และแผนการเดินทาง; ช่างเห็นเฉพาะขั้นของมุมมองตน
- ปุ่ม เริ่ม · หยุดชั่วคราว/เล่นต่อ · ก่อนหน้า · ถัดไป · เริ่มใหม่ · ปิด และ checkbox ปิดเสียง; เน้นส่วนที่กำลังสอนด้วยกรอบสี
- มีไฟล์เสียง → เลื่อนต่อเมื่อเสียงจบ · ปิดเสียง หรือยังไม่มีไฟล์ของขั้นนั้น → แสดงคำบรรยายไทยและเลื่อนตามเวลา (**ไม่ใช้เสียงอื่นแทนเสียงเจ้าของ**)
- เบราว์เซอร์ไม่ยอมเล่นเสียง → หยุดและให้กด “เล่นต่อ” · ซ่อนแท็บ → หยุด · ปิด Demo/ออกจากหน้า → หยุดเสียงทันที · รองรับ reduced motion
- **สถานะเสียง: ยังไม่ได้สร้างไฟล์** — `static/field-service-voice/manifest.json` ว่าง เพราะการสร้างต้องใช้ VoxCPM2 ของ PrintScape บน Mac (GPU) และไฟล์อ้างอิงเสียงของเจ้าของซึ่งอยู่ใน `artifacts/` (ไม่อยู่ใน Git)
  ผู้ช่วยไม่ได้ส่งไฟล์เสียงต้นฉบับออกจากเครื่อง จึงสร้างให้ไม่ได้ ให้รันบน Mac:

```bash
<PrintScape voice venv>/bin/python tools/make-field-service-voice.py --reference artifacts/customer-voice/reference.wav --dry-run   # ดูรายการ
<PrintScape voice venv>/bin/python tools/make-field-service-voice.py --reference artifacts/customer-voice/reference.wav
```
  เครื่องมือสร้างเฉพาะข้อความ `step(...)` ของ `static/field-service-tour.js` ลบเสียงที่ข้อความไม่ตรงแล้ว และเก็บ WAV/โมเดลใน `artifacts/field-service-voice/` (ignored)

## ไฟล์
| ไฟล์ | หน้าที่ |
|---|---|
| `app.py` (+route `/field-service`, +dispatch `/field-service/google/`), `templates/base.html` (+ลิงก์เมนู), `Dockerfile` (+COPY), `docker-compose.yml`/`.env.example` (+ตัวแปร Google ว่างไว้) | การแก้ไฟล์เดิม — เล็กที่สุด |
| `field_service_google.py` | proxy Google Routes ฝั่งเซิร์ฟเวอร์ (คีย์ลับ cache rate limit) |
| `templates/field_service_demo.html`, `static/field-service-demo.css` | หน้า + สไตล์ (ใช้ token ธีมสว่าง/มืดเดิม) |
| `static/field-service-core.js` | ตรรกะล้วน: สถานะ การสรุป ตัวกรอง คิว ภาระงาน คำนวณแผนเดินทาง/คำเตือน/คำแนะนำ |
| `static/field-service-data.js` | ข้อมูลจำลอง (วันที่อิงวันนี้ของเบราว์เซอร์) |
| `static/field-service-demo.js`, `static/field-service-tour.js` | UI และ Demo คำบรรยาย |
| `static/field-service-voice/` | manifest + README (MP3 จะเพิ่มเมื่อสร้างเสียง) |
| `tools/make-field-service-voice.py` | สร้างเสียงแบบ offline |
| `tests/test_field_service_demo.py`, `tests/field_service_demo.test.cjs` | เทสต์ |

## ข้อจำกัดของ Demo รุ่นแรก
ไม่มีการบันทึกจริง ไม่มีสิทธิ์ข้อมูลฝั่งเซิร์ฟเวอร์ ไม่มีรูปถ่ายจริง/ลายเซ็นลูกค้า แผนที่และเส้นทางจริงทำงานเมื่อตั้งคีย์ Google เท่านั้น (ไม่มีจราจรสด) ไม่มีตารางกะช่าง
แผนเดินทางคิดเฉพาะช่างหนึ่งคนต่อวัน จุดเริ่มต้นเป็นศูนย์จำลองจุดเดียว ข้อมูล Demo หายเมื่อปิดแท็บ
